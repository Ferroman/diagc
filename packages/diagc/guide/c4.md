# C4

Context, container and component diagrams with the C4 look: a solid fill for each kind of element, and a `[Type: technology]` line under each name.

{{starter}}

## How it works

- `m.notation('c4')` turns the fills on. Without it the same nodes draw as outlines.
- Elements are ordinary `m.node` calls with a `c4-*` type. There is no C4 builder.
- The levels are containment: a system `contains` its containers, and a container its components. One model holds every level, and the reader drills in.
- `technology` fills the subtitle. `technology: 'Java, Spring Boot'` on a `c4-container-api` prints `[Container: Java, Spring Boot]`.
- Put the protocol in the relation `label`: `'Calls [JSON/HTTPS]'`.

## Node types

{{node-types}}

Pick the most specific one: `c4-container-db` for a database, `c4-container-queue` for a queue, `c4-system-external` for a system you do not own.

## Rules

- Do not set `color` on a C4 node. An explicit colour replaces the notation's fill.
- Relate the elements that actually talk, component to component. Folded, those arrows bundle onto the containers, so the context view still reads.
- Use the general relation kinds: `sync`, `async`, `reads`, `writes`.
